# `infra/helm/observability/` — LTP monitoring stack

Wraps [`prometheus-community/kube-prometheus-stack`](https://github.com/prometheus-community/helm-charts)
and adds LTP-specific resources: `ServiceMonitor`s for `etp-node` /
`etp-gateway`, a generated `PrometheusRule` from
[`src/ltp/observability/alerts.py`](../../../src/ltp/observability/alerts.py),
an `AlertmanagerConfig` that routes critical alerts to PagerDuty, and
three Grafana dashboards (Pause status, Anchor pipeline, Bridge health).

## Prerequisites

- AWS infrastructure from `infra/terraform/envs/prod` is applied (EKS
  cluster + KMS env CMK)
- `external-secrets` is installed in the cluster's `external-secrets`
  namespace, with a `ClusterSecretStore` named `aws-secretsmanager`
  bound to the IRSA role `infra/terraform/envs/prod` exports as
  `external_secrets_role_arn`
- A Secrets Manager entry exists at `ltp/observability/pagerduty-integration-key`
  containing the PagerDuty service-events v2 integration key

## Install

```bash
cd infra/helm/observability
helm dependency update
helm upgrade --install ltp-obs . \
    --namespace observability \
    --create-namespace \
    --values values.yaml \
    --wait
```

The upstream `kube-prometheus-stack` is downloaded into `charts/` at
`dependency update` time; the resolved digest is recorded in
`Chart.lock` (committed). Re-run `helm dependency update` whenever
`Chart.yaml`'s `dependencies` block changes.

## Verify

```bash
helm lint .
helm template ltp-obs . | kubeconform -strict -summary
```

The `infra/helm/observability` CI workflow runs the same two commands
on every PR that touches this directory.

## Refreshing the alert rules

The PrometheusRule in `templates/prometheus-rules-generated.yaml` is
generated by `scripts/export_alert_rules.py`. The Python registry in
`src/ltp/observability/alerts.py` is the source of truth — when you
change the rules there, re-render:

```bash
python3 scripts/export_alert_rules.py \
    > infra/helm/observability/templates/prometheus-rules-generated.yaml
```

CI (PR follow-up) verifies the on-disk file matches a fresh render.

## Pause-runbook integration

When a CRITICAL alert from this stack pages an operator, the OPERATOR_RUNBOOK.md
"Press pause if:" sub-bullets describe whether the alert warrants
flipping the on-chain pause. The flow is:

1. Operator gets paged (PagerDuty)
2. Operator opens the **LTP — Pause status** Grafana dashboard
3. If the appropriate condition holds (per OPERATOR_RUNBOOK §7), the
   operator runs `scripts/propose_pause.sh --rpc-url <env-rpc> --multisig <addr>`
4. Cosigners confirm via the multisig dapp; 0s-delay Timelock executes
5. The dashboard's PAUSE STATUS panel flips red within one scrape interval

## Out of scope

  added to a separate `infra/helm/cluster-bootstrap/` chart later)
- Synthetic load generation (`prometheus-blackbox-exporter`) — added
  once etp-node and etp-gateway are running (Phase C)
- Log aggregation (Loki / CloudWatch) — separate follow-up
